# Ecclesia gap assessment

Source: `ECCLESIA_EXISTING_SYSTEM_ENHANCEMENT_GUIDE.md` (9 Nov 2026). Baseline on branch `claude/dreamy-hypatia-b0bc06`:
`npx vitest run` = 26 files / 911 tests pass; `npx tsc --noEmit` clean.

Status values: working, partial, missing, broken, blocked, verified complete. Statuses below come from reading code,
not from running the app, so nothing here is "verified complete" except where a test is cited.

Architectural fact that shapes everything: **the tenant is the Church**. `Role` is per-church (`Role.churchId`),
`User.churchId` is single, JWT carries `churchId` + flat `permissions[]`. There is no role assignment scoped to a
Circuit/District/Conference/Organisation, and no multi-context switching. Evidence: `prisma/schema.prisma` (Role,
LeadershipAssignment), `src/features/auth/permissions.ts`.

## Recommended order (differs slightly from guide §18 because of the tenant model)

1. ACCESS-1 scoped role assignments (everything in phases 1, 2, 4, 6 needs it).
2. ORG-2 web form, ORG-3/4 Secretary + onboarding.
3. MEM-1..4 import hardening.
4. LEAD-1/2 catalogue + importer.
5. POS session state machine + review.
